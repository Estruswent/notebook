    数制与编码

    一、数制基础与转换

    1. 常见数制

    日常生活中我们使用 十进制（Decimal），但计算机内部使用 二进制（Binary） 来表示一切数据。为了书写方便，还常用 八进制（Octal） 和 十六进制（Hexadecimal） 作为二进制的缩写形式。

    数制 基数 数码 前缀标记（C语言） 示例
    二进制 2 0, 1 0b 或 0B 0b1010
    八进制 8 0~7 0 012
    十进制 10 0~9 无 10
    十六进制 16 0~9, A~F 0x 或 0X 0xA

    以上四个数在数值上是相等的，都表示十进制的 10。

    2. 任意进制 → 十进制

    方法：按权展开求和。 每一位的数码乘以其对应的位权，然后全部加起来。

    对于一个 \(n\) 位的 \(r\) 进制数 \( (d_{n-1} d_{n-2} \dots d_1 d_0)_r \)，其十进制值为：

    \[ D = \sum_{i=0}^{n-1} d_i \times r^i \]

    如果还有小数部分 \( (d_{-1} d_{-2} \dots d_{-m})_r \)，则继续累加：

    \[ D = \sum_{i=0}^{n-1} d_i \times r^i + \sum_{j=1}^{m} d_{-j} \times r^{-j} \]

    二进制转十进制

    将 \( (1101.101)_2 \) 转换为十进制：

    \[ 1 \times 2^3 + 1 \times 2^2 + 0 \times 2^1 + 1 \times 2^0 + 1 \times 2^{-1} + 0 \times 2^{-2} + 1 \times 2^{-3} \]
    \[ = 8 + 4 + 0 + 1 + 0.5 + 0 + 0.125 = \boxed{13.625} \]

    十六进制转十进制

    将 \( \text{0x1F.C} \) 转换为十进制：

    \[ 1 \times 16^1 + 15 \times 16^0 + 12 \times 16^{-1} = 16 + 15 + 0.75 = \boxed{31.75} \]

    3. 十进制 → 任意进制

    3.1 整数部分：除基取余，逆序排列

    将十进制整数反复除以目标进制的基数，每次记录余数，直到商为 0。余数从下往上（逆序）排列即为结果。

    十进制转二进制

    将 \( 25_{10} \) 转换为二进制：

    除法 商 余数
    25 ÷ 2 12 1
    12 ÷ 2 6 0
    6 ÷ 2 3 0
    3 ÷ 2 1 1
    1 ÷ 2 0 1

    逆序排列余数：\( 25_{10} = \boxed{11001_2} \)

    3.2 小数部分：乘基取整，顺序排列

    将十进制小数反复乘以目标进制的基数，每次取走整数部分，直到小数部分为 0（或达到所需精度）。整数部分从上往下（顺序）排列即为结果。

    十进制转二进制

    将 \( 0.6875_{10} \) 转换为二进制：

    乘法 结果 取整
    0.6875 × 2 1.375 1
    0.375 × 2 0.75 0
    0.75 × 2 1.5 1
    0.5 × 2 1.0 1

    顺序排列整数：\( 0.6875_{10} = \boxed{0.1011_2} \)

    小数转换可能无法精确表示

    不是所有十进制小数都能用有限位二进制精确表示。例如 \( 0.1_{10} \) 在二进制中是无限循环小数 \( 0.0001100110011\dots_2 \)，这就是为什么计算机中浮点数运算会出现精度误差。

    4. 二进制与八进制/十六进制的快速互转

    由于 \( 8 = 2^3 \)、\( 16 = 2^4 \)，二进制与八/十六进制之间的转换可以直接按位分组，无需经过十进制中转。

    • 二进制 → 八进制：每 3 位二进制一组（整数部分从右往左，小数部分从左往右），不足补 0。
    • 二进制 → 十六进制：每 4 位二进制一组。

    二进制转十六进制

    将 \( 10110101.11_2 \) 转换为十六进制：

    整数部分从右往左分组：1011 0101 → B 5

    小数部分从左往右分组：1100（补 0 凑齐 4 位）→ C

    结果：\( 10110101.11_2 = \boxed{\text{0xB5.C}} \)

    八进制转二进制

    将 \( 57.2_8 \) 转换为二进制：

    • \( 5_8 = 101_2 \)
    • \( 7_8 = 111_2 \)
    • \( 2_8 = 010_2 \)

    结果：\( 57.2_8 = \boxed{10111.01_2} \)

    二、带符号整数的编码

    计算机中整数不仅需要表示数值的大小，还需要表示正负号。常见的编码方式有三种。

    1. 原码（Sign-Magnitude）

    最高位为符号位（0 表示正，1 表示负），其余位为数值的绝对值。

    对于 \(n+1\) 位原码（1 位符号位 + \(n\) 位数值位），表示范围为：

    \[ -(2^n - 1) \leq x \leq 2^n - 1 \]

    以 8 位原码为例，表示范围为 \(-127 \sim +127\)。

    原码中 0 有两个编码

    原码中 \( +0 \) 和 \( -0 \) 的编码不同：

    • \( +0 = 0\ 0000000 \)
    • \( -0 = 1\ 0000000 \)

    这导致编码空间浪费了一个码点，且硬件实现加减法比较复杂。

    2. 反码（One's Complement）

    • 正数的反码与原码相同。
    • 负数的反码：符号位不变，数值位逐位取反（0 变 1，1 变 0）。

    对于 \(n+1\) 位反码，表示范围同样为：

    \[ -(2^n - 1) \leq x \leq 2^n - 1 \]

    Note

    反码同样存在 \( +0 \) 和 \( -0 \) 两个编码的问题：

    • \( +0 = 0\ 0000000 \)
    • \( -0 = 1\ 1111111 \)

    反码在现代计算机中已很少直接使用，但它在补码的推导中起到桥梁作用。

    3. 补码（Two's Complement）—— 现代计算机的标准

    补码是当今计算机表示带符号整数的主流方式。

    定义：

    • 正数的补码与原码相同。
    • 负数的补码：在其反码的基础上 加 1。

    等价地，一个负数 \(-x\) 的补码也可以理解为：\( 2^{n+1} - x \)（即以 \( 2^{n+1} \) 为模）。

    对于 \(n+1\) 位补码，表示范围为：

    \[ -2^n \leq x \leq 2^n - 1 \]

    以 8 位补码为例，表示范围为 \(-128 \sim +127\)，比原码多表示一个数。

    求 -5 的 8 位补码

    方法一：原码 → 反码 → 补码

    1. 原码：\( 1\ 0000101 \)
    2. 反码（数值位取反）：\( 1\ 1111010 \)
    3. 补码（加 1）：\( 1\ 1111011 \)

    方法二：\( 2^8 - 5 = 256 - 5 = 251 = 11111011_2 \)

    结果：\( -5_{10} = \boxed{11111011_2} \)（补码）

    补码中 0 的编码唯一

    补码中 \( +0 \) 和 \( -0 \) 的编码相同：

    • \( +0 = 0\ 0000000 \)
    • \( -0 \)：先取反得 \( 1\ 1111111 \)，再加 1 得 \( 0\ 0000000 \)（溢出部分丢弃）

    正因为 0 的编码唯一，补码可以多表示一个数（即 \(-128\)）。

    4. 三种编码方式对比（8 位）

    十进制 原码 反码 补码
    +127 01111111 01111111 01111111
    +1 00000001 00000001 00000001
    +0 00000000 00000000 00000000
    -0 10000000 11111111 00000000
    -1 10000001 11111110 11111111
    -127 11111111 10000000 10000001
    -128 无 无 10000000

    5. 为什么补码能简化硬件设计？

    补码的核心优势在于：减法可以转化为加法。

    在补码体系下，\( A - B = A + (-B) \)，而 \( -B \) 的补码恰好等于对 \( B \) 的补码按位取反再加 1。因此计算机只需要一个加法器就能同时处理加法和减法，大大简化了硬件设计。

    例如计算 \( 7 - 5 \)（8 位）：

    1. \( 7 \) 的补码：\( 00000111 \)
    2. \( -5 \) 的补码：\( 11111011 \)
    3. 相加：\( 00000111 + 11111011 = 1\ 00000010 \)
    4. 丢弃溢出位，结果为 \( 00000010 = 2_{10} \) ✓

    三、C 语言中整数的表示

    C 语言中的整数类型在内存中以补码形式存储。常见的整数类型及其典型大小：

    类型 字节数 位数 表示范围（补码）
    char 1 8 \(-128 \sim 127\)
    short 2 16 \(-32768 \sim 32767\)
    int 4 32 \(-2^{31} \sim 2^{31}-1\)
    long long 8 64 \(-2^{63} \sim 2^{63}-1\)

    以上大小以 32 位/64 位主流平台为准，long 的大小因平台而异（Windows 为 4 字节，Linux 64 位为 8 字节）。

    1. 不涉及字长变化：改变解释含义

    同一段二进制数据，用不同的类型去解释，会得到不同的数值。这在 C 语言中通过强制类型转换（不改变底层比特位，只改变解释方式）实现。

    有符号 vs 无符号

    假设内存中存储了 11111111（8 位）：

    • 作为 signed char（补码）解释：\( -1 \)
    • 作为 unsigned char 解释：\( 255 \)

    在 C 语言中：

    char a = -1;
unsigned char b = (unsigned char)a;
// a 的补码：11111111
// b 将 11111111 解释为无符号数：255

    隐式转换规则

    当 signed 和 unsigned 混合运算时，C 语言会将 signed 隐式转换为 unsigned 后再运算。这可能导致意想不到的结果：

    int a = -1;
unsigned int b = 1;
if (a < b) {
    printf("a < b\n");
} else {
    printf("a >= b\n");  // 实际输出这个！
}

    因为 -1 的补码是 0xFFFFFFFF，被解释为无符号数后变成 \( 2^{32} - 1 = 4294967295 \)，远大于 1。

    2. 涉及字长变化

    2.1 位截断（Truncation）

    将一个较长类型的整数赋值给较短类型时，高位直接丢弃。

    int x = 256;        // 二进制：00000000 00000000 00000001 00000000
char y = (char)x;   // 截取低 8 位：00000000，结果为 0

    int x = 257;        // 二进制：00000000 00000000 00000001 00000001
char y = (char)x;   // 截取低 8 位：00000001，结果为 1

    截断可能导致数值剧变

    对于有符号数，截断还可能改变正负性：

    int x = 128;        // 二进制：00000000 00000000 00000000 10000000
char y = (char)x;   // 截取低 8 位：10000000（补码），结果为 -128

    2.2 位拓展（Extension）

    将一个较短类型的整数赋值给较长类型时，需要在高位填充额外的位。

    • 零拓展（Zero Extension）：高位补 0。用于 无符号数 的拓展。
    • 符号拓展（Sign Extension）：高位补符号位的副本。用于 有符号数 的拓展。

    符号拓展 vs 零拓展

    将 signed char a = -5（补码 11111011）拓展为 16 位：

    • 符号拓展：11111111 11111011 → 仍然是 \( -5 \) ✓

    将 unsigned char b = 251（二进制 11111011）拓展为 16 位：

    • 零拓展：00000000 11111011 → 仍然是 \( 251 \) ✓

    如果对 251 错误地做符号拓展：11111111 11111011 → \( -5 \) ✗（数值完全变了）

    Note

    符号拓展之所以正确，是因为补码的数学性质：对于负数，高位补 1 不改变其数值。可以这样理解——补码中高位的 1 代表的是负权值，补更多的 1 相当于减去相同的值再加回来，净效果为零。

    四、浮点数的表示（IEEE 754）

    1. 为什么需要浮点数？

    定点数（整数）无法表示非常大或非常小的实数。浮点数通过科学计数法的思想，用有限的位数表示极大范围的数值。

    一个浮点数可以写成：

    \[ V = (-1)^S \times M \times 2^E \]

    其中：

    • \(S\)：符号位（Sign），0 为正，1 为负。
    • \(M\)：尾数（Mantissa/Significand），表示有效数字。
    • \(E\)：阶码（Exponent），表示小数点的位置（即 2 的幂次）。

    2. IEEE 754 单精度（32 位）格式

    32 位被划分为三个字段：

    字段 位数 位置 说明
    符号位 \(S\) 1 位 第 31 位 0 正 1 负
    阶码 \(E\) 8 位 第 30~23 位 移码表示（偏置值 127）
    尾数 \(M\) 23 位 第 22~0 位 隐含一个前导 1

    关键细节：

    • 偏置阶码（Biased Exponent）：阶码字段存储的不是 \(E\) 的真值，而是 \(E + 127\)（即移码）。这样做的好处是可以用无符号整数来比较浮点数的大小。
    • 隐含前导 1（Hidden Leading 1）：规格化数的尾数部分省略了小数点前的 1（因为二进制科学计数法中，规格化后这一位一定是 1），只存储小数点后的部分，从而多获得 1 位精度。

    3. 规格化数（Normalized）

    当阶码字段 \( \neq 0 \) 且 \( \neq 255 \) 时，该浮点数为规格化数。

    \[ V = (-1)^S \times 1.M \times 2^{E - 127} \]

    其中 \( 1.M \) 表示小数点前隐含一个 1，后面跟 23 位小数。

    将十进制转换为 IEEE 754 单精度

    将 \( -5.75_{10} \) 转换为 IEEE 754 单精度表示。

    步骤一：转换为二进制

    \( 5.75_{10} = 101.11_2 \)

    步骤二：规格化

    \( 101.11_2 = 1.0111 \times 2^2 \)

    步骤三：确定各字段

    • \(S = 1\)（负数）
    • \(E = 2 + 127 = 129 = 10000001_2\)
    • \(M = 01110000000000000000000\)（去掉隐含的 1，后面补 0）

    步骤四：拼接

    \[ 1\ 10000001\ 01110000000000000000000 \]

    十六进制表示：\( \boxed{\text{0xC0B80000}} \)

    4. 非规格化数（Denormalized）

    当阶码字段全为 0（即 \(E_{\text{field}} = 0\)），但尾数字段不为 0 时，该数为非规格化数。

    \[ V = (-1)^S \times 0.M \times 2^{-126} \]

    与规格化数的区别：

    • 尾数不再隐含前导 1，而是 \( 0.M \)。
    • 阶码固定为 \( -126 \)（而非 \( 0 - 127 = -127 \)）。

    非规格化数的作用

    非规格化数用于表示非常接近零的数。如果没有非规格化数，从最小规格化数到零之间会出现一段"间隙"，导致精度突然下降（称为下溢间隙）。非规格化数填补了这个间隙，实现了渐进下溢（Gradual Underflow）。

    5. 特殊值

    当阶码字段全为 1（即 \(E_{\text{field}} = 255\)）时，表示特殊值：

    条件 值 含义
    \(E_{\text{field}} = 255\)，\(M = 0\) \(\pm \infty\) 无穷大（符号由 \(S\) 决定）
    \(E_{\text{field}} = 255\)，\(M \neq 0\) \(\text{NaN}\) Not a Number，非数

    常见的产生 NaN 的运算：\( 0 / 0 \)、\( \infty - \infty \)、\( \sqrt{-1} \) 等。

    6. 双精度（64 位）

    IEEE 754 双精度格式与单精度类似，但使用更多位数来获得更高的精度和范围：

    字段 位数 位置 说明
    符号位 \(S\) 1 位 第 63 位 0 正 1 负
    阶码 \(E\) 11 位 第 62~52 位 移码表示（偏置值 1023）
    尾数 \(M\) 52 位 第 51~0 位 隐含一个前导 1

    表示范围约为 \(\pm 1.8 \times 10^{308}\)，有效数字约为 \(15 \sim 17\) 位十进制。

    7. 舍入模式

    浮点数运算的结果可能无法精确表示，需要进行舍入（Rounding）。IEEE 754 定义了四种舍入模式：

    舍入模式 说明
    向最近值舍入（Round to Nearest） 默认模式，结果舍入到最近的可表示值；若恰好在中间，则舍入到偶数位
    向零舍入（Round toward Zero） 直接截断多余位
    向正无穷舍入（Round toward \(+\infty\)） 向上取整
    向负无穷舍入（Round toward \(-\infty\)） 向下取整

    舍入误差的经典例子

    在大多数语言中（使用 IEEE 754 双精度），以下表达式的结果并不是精确的 \( 0.3 \)：

    >>> 0.1 + 0.2
0.30000000000000004

    这是因为 \( 0.1_{10} \) 和 \( 0.2_{10} \) 在二进制中都是无限循环小数，存储时已经产生了微小的舍入误差。

    五、编码补充

    1. BCD 码（Binary-Coded Decimal）

    BCD 码用 4 位二进制来表示 1 位十进制数码。最常用的是 8421 码，即每位的权值分别为 8、4、2、1。

    十进制 8421 BCD 码
    0 0000
    1 0001
    2 0010
    3 0011
    4 0100
    5 0101
    6 0110
    7 0111
    8 1000
    9 1001

    注意：\( 1010 \sim 1111 \) 这 6 个编码在 8421 BCD 码中是无效的。

    BCD 码表示

    十进制数 \( 259_{10} \) 用 8421 BCD 码表示为：

    \[ 2 \rightarrow 0010,\quad 5 \rightarrow 0101,\quad 9 \rightarrow 1001 \]

    结果：\( \boxed{0010\ 0101\ 1001}_{\text{BCD}} \)

    BCD 码广泛用于需要精确十进制表示的场合（如金融计算、数字钟表显示等），因为它避免了二进制浮点数的舍入误差。

    2. 字符编码：ASCII 与 Unicode

    2.1 ASCII

    ASCII（American Standard Code for Information Interchange）用 7 位二进制编码 128 个字符，包括：

    • 可打印字符（32~126）：英文字母、数字、标点符号等。
    • 控制字符（0~31，127）：如换行 \n（10）、回车 \r（13）、制表 \t（9）等。

    一些关键的 ASCII 码值需要记牢：

    字符 ASCII 码（十进制） ASCII 码（十六进制）
    '0' 48 0x30
    '9' 57 0x39
    'A' 65 0x41
    'Z' 90 0x5A
    'a' 97 0x61
    'z' 122 0x7A
    ' '（空格） 32 0x20

    大小写字母的转换

    观察上表可以发现：'A'（65）与 'a'（97）的差值为 32，即二进制的第 5 位不同。因此：

    • 大写转小写：ch | 0x20（将第 5 位置 1）
    • 小写转大写：ch & 0xDF（将第 5 位清 0）

    2.2 Unicode 与 UTF-8

    ASCII 只能表示 128 个字符，无法覆盖中文、日文等文字。Unicode 为世界上几乎所有的字符分配了唯一的码点。

    UTF-8 是 Unicode 最常用的编码方式，它是一种变长编码：

    码点范围 字节数 编码格式
    U+0000 ~ U+007F 1 字节 0xxxxxxx
    U+0080 ~ U+07FF 2 字节 110xxxxx 10xxxxxx
    U+0800 ~ U+FFFF 3 字节 1110xxxx 10xxxxxx 10xxxxxx
    U+10000 ~ U+10FFFF 4 字节 11110xxx 10xxxxxx 10xxxxxx 10xxxxxx

    UTF-8 的设计非常巧妙：

    • ASCII 范围内的字符（U+0000 ~ U+007F）用 1 字节表示，与 ASCII 完全兼容。
    • 每个字节的前缀标明了该字节的角色（起始字节 or 后续字节），使得在任意位置截断都能正确恢复字符边界。
    • 对于中文字符，通常需要 3 个字节。
